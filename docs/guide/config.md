# Configuration

The installed `litti` command reads settings from environment variables and from `~/.litti/config.env`. Environment variables win. Restart `litti` after changing them.

On the first run `litti` creates `config.env` with a random `SECRET_KEY` and a random `LITTI_ADMIN_KEY`. It never reads a project's `.env`, so a repository can't change Litti's settings. Running from source (`npm run demo`, `tsx src/index.ts`) or in Docker? Then Litti reads the `.env` next to it instead (copy `.env.example`).

## Core

| Variable | Default | Purpose |
|---|---|---|
| `SECRET_KEY` | generated by `litti`; **required** otherwise | 32+ random characters. Signs tokens, review links and page stamps; encrypts integration tokens |
| `APPROVAL_SERVER_PORT` | `3847` | Port. The CLI and agent hooks read it from `config.env` too |
| `HOST` | `127.0.0.1` | Interface to listen on. Anything other than loopback (`0.0.0.0` in Docker) **refuses to start** unless `LITTI_API_KEY` or `LITTI_API_KEYS` is set |
| `PUBLIC_URL` | `http://127.0.0.1:<port>` | Base URL in links. **Required** when an agent key is set. Use https in production. While Litti listens on 127.0.0.1 it only answers requests addressed to `127.0.0.1`, `localhost`, `[::1]` or this host (DNS-rebinding guard) |
| `LITTI_HOME` | `~/.litti` | Folder for `config.env`, the database and deploy records |
| `LITTI_DB_PATH` | `~/.litti/litti.db` (`litti`); `data/litti.db` (from source) | SQLite file |
| `LITTI_DEMO_DB` | `~/.litti/demo.db` (`litti demo`); `litti-demo.db` (from source) | Demo database, wiped on every `litti demo` |
| `LOG_LEVEL` | `info` | Request log level. Logs never contain client IPs, the machine name or query strings |
| `TRUST_PROXY` | | `true` to trust `X-Forwarded-*` behind a reverse proxy |

## Access

| Variable | Purpose |
|---|---|
| `LITTI_API_KEY` | One shared agent key. Agents, CLI and pipelines send it as `x-litti-key`. Turns on team mode |
| `LITTI_API_KEYS` | Labelled agent keys: `ci-bot:key1,claude-ana:key2`. The label becomes the requester shown on the review, so an agent can't pick its own name. Also turns on team mode |
| `LITTI_ADMIN_KEY` | Issues personal review links (`litti review`, `POST /api/actions/:id/review-link`). **Always required for review links**, locally too. `litti` generates one in `config.env`; set it yourself from source or in Docker. Keep it away from agents (the agent hook refuses commands that read it) |
| `LITTI_LOCAL_REVIEWER` | Who you are when you review on your own machine. Default: your OS user name. Only used in local mode (no agent key, no SSO header, loopback `HOST`, request from this machine) |
| `LITTI_IDENTITY_HEADER` | Trust this header from your SSO proxy as the reviewer's identity, e.g. `x-forwarded-email` |
| `LITTI_ADMINS` | SSO identities allowed to manage `/integrations` in team mode |
| `LITTI_ALLOW_SELF_ASSERTED` | `true` lets reviewers type a name. The demo turns it on; leave it off everywhere else |

## Review

| Variable | Purpose |
|---|---|
| `LITTI_CHALLENGES` | Allowed check kinds: `quiz,spot-line,type-in,canary,count,explain` (default: all) |

## Changes view

| Variable | Purpose |
|---|---|
| `LITTI_REPO_PATH` | Git repository to watch (default: where Litti runs) |
| `LITTI_AGENT_NAME` | Name shown for agent replies and review requests. It can't be the same as the local reviewer |

## Agent hooks

The hook reads these from its own environment and from `~/.litti/config.env` (or `$LITTI_HOME/config.env`). It never reads the project's `.env`.

| Variable | Purpose |
|---|---|
| `LITTI_URL` | Litti's address (default `http://127.0.0.1:<APPROVAL_SERVER_PORT>`) |
| `LITTI_API_KEY` | The agent key, if the server needs one |
| `LITTI_AGENT_NAME` | Name shown on review requests (with `LITTI_API_KEYS` the key's label wins) |
| `LITTI_GATE_COMMIT` | `false` stops gating `git commit` |
| `LITTI_GATE_PATTERNS` | Extra commands to gate: regexes separated by `;;` |
| `LITTI_HOOK_DEADLINE_MS` | How long the hook may take before it denies (default 20000). Environment only |
| `LITTI_HOOK_FAIL_OPEN` | `true` allows commands when Litti is down. Not for production |

## Notifications

The [Integrations page](connect-team) is the easy way. These do the same from config:

| Variable | Purpose |
|---|---|
| `LITTI_NOTIFY_WEBHOOK` | Slack or Discord incoming webhooks, comma-separated (plain text) |
| `SLACK_BOT_TOKEN`, `SLACK_CHANNEL` | Slack app: threaded cards |
| `LITTI_DISCORD_WEBHOOK` | Discord embeds |
| `JIRA_BASE_URL`, `JIRA_PROJECT_KEY`, `JIRA_API_TOKEN`, `JIRA_EMAIL` | Jira with an API token (`JIRA_EMAIL` only for Jira Cloud) |
| `JIRA_ISSUE_TYPE`, `JIRA_MIN_TIER`, `JIRA_DONE_TRANSITION` | Issue type (default `Task`), lowest tier that opens an issue (default 2), status to move to on approval |
| `SLACK_CLIENT_ID`/`_SECRET`, `DISCORD_CLIENT_ID`/`_SECRET`, `ATLASSIAN_CLIENT_ID`/`_SECRET` | Connect-button app credentials, instead of pasting them on the page |
| `LITTI_CONNECT_BROKER` | URL of a [Litti Connect](https://github.com/Abhishek764/litti/blob/main/docs/connect-service.md) service for one-click buttons (https, or loopback for testing). Unset or `off`: one-click is off |

Notifications carry the description, the command, file names, risk reasons and the diff's hash. Diffs are never sent.

## Running approved actions

| Variable | Purpose |
|---|---|
| `LITTI_DEPLOY_WEBHOOK` | Approved actions are POSTed here, signed in `x-litti-signature` |
| `LITTI_WEBHOOK_SECRET` | Signing key for that webhook (default: `SECRET_KEY`) |
| `LITTI_WEBHOOK_TIMEOUT_MS` | How long to wait for the webhook (default 15000). A failure records `deploy-failed` |
| `LITTI_DEPLOY_DIR` | Where deploy records go when no webhook is set (default `~/.litti/deployments`, or `deployments` from source) |
