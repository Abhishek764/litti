Proof of review for AI coding agents

Your approve button is a spring lock. Litti makes sure someone turned the key.

Litti blocks your coding agent's risky commands (commits, pushes, deploys, migrations, big deletes) until a human reads the diff and answers one question about it. Every approval is bound to the exact change and written to a tamper-evident receipt.

$ npm install -g litti
$ litti demo

"Allow this command?" Yes. Yes. Yes.

Coding agents ask for permission many times a day, and people say yes almost every time. An approve button records that someone clicked. It doesn't record that anyone looked. That's fine for ls. It isn't fine for git push --force, DROP TABLE or terraform apply.

Fast stays fast. Risky waits for a human.

Litti plugs into your agent as a hook. Reading files, editing, tests and builds go through untouched.

1

Your agent is stopped, not slowed

When the agent tries a commit, push, deploy, migration or destructive command, the hook denies it at once and tells the agent to wait for review. If the hook can't reach Litti, it still denies.

2

You read it and prove it

The review page shows the command and the code it would ship. Scroll to the end and answer one question built from the diff. Riskier changes need more reviewers, and you can't approve your own request.

3

It runs once. The receipt stays.

The agent retries the same command and it goes through, once. Change one byte and it's a new review. The decision is chained into a receipt log that litti verify checks for tampering.

One question. A different kind each time.

Clicking a box proves nothing. Litti asks about the change itself, and the kind of question usually changes from one review to the next. No AI writes the questions: they come from rules and the diff.

Quiz"Which table does this migration alter?" Pick from four.
Spot the line"Click the line that permanently deletes data."
RecallType the name of the function this change modifies. No options to guess from.
CanaryIs this line really in the change, or was one word quietly altered?
CountHow many lines does this change remove? (small diffs only)
Explain itOne sentence in your own words, saved in the receipt.

What's in the box

Risk tiers, no AI

Every action gets a tier from 0 to 3 from plain rules: paths like migrations/, auth/, .env, diff size and destructive commands. The tier sets how many reviewers it needs.

Catches rubber-stamping

Approve a big diff in seconds or answer wrong, and Litti blocks it, resets every review on that action and makes the next one stricter.

Bound to the exact diff

Approval is a signed, single-use token tied to the SHA-256 of the change. Edit one byte or replay it and it's refused.

Receipts you can verify

Each decision is hash-chained to the one before. litti verify points at the first entry anyone edited.

Talk it through

The Changes view shows the agent's edits live. Comment on a line and the agent replies in the same thread.

Tells your team

Slack, Discord and Jira get a card with a Review button. Nobody can approve from chat: the button opens the review page.

Also: a litti CLI and HTTP API for any agent or pipeline, a signed webhook to your CI/CD, and docker compose up -d for a team server.

Built for people who read threat models

What Litti enforces

  • Risky commands are denied until approved; the executor refuses without a valid, unused token.
  • The requester never counts as a reviewer.
  • Review time is measured by the server, not the browser.
  • Approval is bound to the SHA-256 of the exact diff and works once.
  • Receipts are hash-chained; litti verify points at the first broken link.
  • Tiers and questions come from rules, not a model. Diffs stay on your machine.

What Litti doesn't do (yet)

  • It gates risky shell commands by pattern, not by parsing shell. A determined agent can hide a push inside a script.
  • It proves a reviewer passed the check, not that the reviewer wasn't a browser automation.
  • Receipts are hash-chained but not signed, so someone with write access to the database could rewrite the whole chain.
  • It isn't a sandbox or a network firewall. Pair it with one.

Questions

Doesn't this slow my agent down?

Only for risky actions. Tests, builds, reading and editing files never wait. If gating plain commits is too much, set LITTI_GATE_COMMIT=false and keep pushes, deploys and migrations gated.

Can my agent just answer the question itself?

The agent can't approve through the hook, and the requester never counts as a reviewer. An agent that can drive your logged-in browser is a real risk; see SECURITY.md for the details and open issues.

Does any code leave my machine?

Diffs don't. If you connect Slack, Discord or Jira, they get the action's description, the command, file names, risk reasons and the diff's hash. Litti makes no LLM calls.

Is this a replacement for pull request review?

No. PR review happens after the agent has already pushed. Litti sits earlier: before the push, the migration or the deploy.

What does "tamper-evident" mean here?

Each receipt includes the hash of the one before it. Edit an old receipt and every later hash stops matching; litti verify names the first broken one. It shows tampering; it doesn't prevent it.

Is it free?

Yes, MIT licensed, and it runs on your machine with no account.
